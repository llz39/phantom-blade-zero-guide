再写入，MySQL 侧按 `doc_id` 做 `ON DUPLICATE KEY UPDATE`。

### 4. 失败可定位

每篇独立 try/except，失败写入 `failures[{file, error}]`，不静默跳过；退出码非 0。

### 入库时踩到并修掉的两个硬问题

1. **主键超长**：`id = doc_id#chunk_index` 会到 67–72 字节，超过 Milvus VARCHAR(64) 限制。
   改为 `sha1(doc_id#index)`（固定 40 位十六进制），幂等且稳定。
2. **doc_id 超长**：`game:type:entity:version` 遇到
   `weapon_white_serpent_crimson_viper` 是 70 字节，同样写不进去。
   收敛为 `pbz:{doc_type}:{entity_id}`（version 单独作为标量字段），
   换版本时按 doc_id 先删后写，语义仍是「最新版本覆盖」。

修完后 `--rebuild` 全量重灌：72 篇全部成功，条数一一对应。
