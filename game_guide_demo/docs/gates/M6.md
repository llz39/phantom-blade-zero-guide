### 3. 回答规则（代码层强制）

| 规则 | 实现位置 |
|---|---|
| 只依据知识库 | `RAG_PROMPT_TEMPLATE` 第 1 条 + `[NO_RAG_ANSWER]` 标记 |

| 上下文成本 | 上下文 ≤ 7000 字符、top_k ≤ 6、输出 ≤ 800 tokens |
| 重试 | `_generate_rag_answer` 最多 2 次尝试（1 次重试） |

## 本轮修掉的两个真实缺陷

1. **空回复**：`action_default_fallback` 只负责压 `CannotHandleStackFrame`，
   而策略的“刚执行过动作就弃权”判断把它跳过了 → 下一轮直接 `action_listen`，用户看到 0 条响应。
   修复：把 `CannotHandleStackFrame` 加入 `needs_immediate_handling`。
2. **兜底话术过窄**：原 `utter_default` 只讲“数值”，遇到“其他游戏/剧透”时措辞不对。
   改为通用口径，同时保留 `暂未收录` 字样，保证前端与评测脚本能识别 unknown。

## 本轮又修掉的两个交互缺陷

1. **Flow 卡死**：`ask_before_filling: true` 导致「玉璧怎么打」已经带了实体名，
   Flow 仍然再问一遍“要查哪个 Boss？”，之后每条消息都被当成槽位值吞掉。
   修复：去掉三个 Flow 的 `ask_before_filling`，并在提示词里允许「start flow + set slot」同轮完成。
2. **LLM 空输出被当成拒答**：qwen 偶发返回空串 → `parse_failed` → 直接拒答。
   修复：空输出用更短指令重试一次；仍失败则降级为 `knowledge_answer` 继续检索，
   宁可多检索一次，也不要误拒答。
